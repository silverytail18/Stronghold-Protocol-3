# 段位版本：源码部署与使用

`Stronghold-Protocol-Ranked` 是原项目的独立副本，版本 `0.2.6`，APK versionCode 为 9。原目录 `Stronghold-Protocol` 保留。普通模拟、素材、账号管理与安卓横屏状态栏修复沿用原实现。

## 公网 IP + HTTP 源码部署

使用 **Node.js 22.16.0 及以上**，本版本在 Node.js 24.11.1 验证。使用 Node 内置 `node:sqlite`，无需安装数据库服务或 Docker。Node 可能打印 SQLite 实验性 API 提示。

上传本副本源码和已有素材到服务器，例如 `/opt/Stronghold-Protocol-Ranked`。不要把 Windows 的 `node_modules` 或 `.cache` 当作 Linux 依赖上传。

```bash
cd /opt/Stronghold-Protocol-Ranked
npm ci
# 如已有 public/assets 与 data，无需重新下载素材；缺少时使用 npm run setup。
test -f config/server.env || cp config/server.env.example config/server.env
node --env-file=config/server.env server/index.js
```

检查 `config/server.env`：

```dotenv
HOST=0.0.0.0
PORT=3000
SP_AUTH=on
SP_AUTH_COOKIE_SECURE=0
SP_AUTH_SESSION_HOURS=12
SP_RANKED=on
SP_RANKED_MAX_MATCHES=4
```

网页游戏为 `http://公网IP:3000/`，管理员后台为 `http://公网IP:3000/admin`，普通用户改密码为 `/account`。只需放行 TCP 3000。Linux 常驻服务可沿用 [AUTH.md](AUTH.md) 的 systemd 示例，把目录改为本副本。无需域名、HTTPS 或 Docker。

PowerShell 本地启动：

```powershell
cd C:\Users\silve\Documents\vscode\codex\wei\Stronghold-Protocol-Ranked
if (!(Test-Path config/server.env)) { Copy-Item config/server.env.example config/server.env }
node --env-file=config/server.env server/index.js
```

副本保留复制时的账号文件，首次启动会为已有账号补充不可变的 `accountId`，密码不变。没有账号文件时才创建默认管理员 `admin` / `Stronghold@123456`，首次通过网页修改初始密码。新密码最低 **6 个字符**，最大 256 字节；账号创建、登录、修改、重置和命令行密码恢复规则一致。

## 玩家入口、积分与段位

在「选择模拟协议」选择险境、绝境或终极，勾选「开启排位赛」。同盟房主也可在准备界面切换排位，切换后队员重新准备。标准模拟不开放排位。点击段位按钮查看排行榜、历史赛季、个人战绩和规则，战绩可筛选单人 / 同盟。

每个账号每赛季只有一套积分和段位，单人 / 同盟合并，无定级赛。新赛季全员从 **青铜 III、0 分**开始。

| 难度 | 单人胜利 | 同盟胜利，每人 | 失败，每人 | 单人 / 同盟隐秘核心额外奖励 |
|---|---:|---:|---:|---:|
| 险境 | +30 | +15 | −20 | +4 / +2 |
| 绝境 | +40 | +20 | −25 | +8 / +4 |
| 终极 | +60 | +30 | −30 | +12 / +6 |

同盟按团队结果给所有正常参赛者相同积分，击杀不影响奖励；正常淘汰者仍可获得团队胜利分。失败扣分与同难度单人相同，不按段位、击杀或回合数浮动。积分最低 0，因此实际扣分可能低于标准扣分。

第 14 回合主线通关锁定胜利，核心失败保留主线胜利分。核心通关额外加分。主线通关后离开保留基础胜利分，不领取后来完成的核心奖励。结算页显示本局积分变化与前后段位。

| 段位 | 积分 |
|---|---:|
| 青铜 | 0–299 |
| 白银 | 300–599 |
| 黄金 | 600–899 |
| 铂金 | 900–1199 |
| 钻石 | 1200–1499 |
| 大师 | 1500–1799 |
| 传奇 | 1800 及以上 |

青铜至大师分 III / II / I，每 100 分一级，正常升降级。600 分起仅能开始绝境 / 终极，1200 分起仅能开始终极。同盟全员必须满足难度，等效按最高积分队员选择。开局时合格的跨段位胜局仍获得完整分数。

## 真人、断线和放弃

- 单人 1 名真人，同盟 2–4 名真人；排位禁用 AI 队友；普通玩家不可 AI 托管，管理员可在全部排位使用本人私有的托管入口，详见 [PERSISTENCE.md](PERSISTENCE.md)。
- 同账号不能重复占座，也不能同时有多场进行中 / 待结算排位。
- 断线后 10 分钟内重新登录可恢复原排位，跨设备无需旧游戏令牌；新连接替代旧连接。普通单人原有 24 小时重连规则保留。
- 主线前、尚未正常淘汰时主动离开或重连超时，按失败扣分，不领取后续团队奖励。仅单人排位：24 小时内第一次 / 第二次 / 第三次及以上放弃，分别冷却 5 / 15 / 30 分钟。多人排位不设置冷却；单人冷却期间仍可创建、加入和开始多人排位。旧多人冷却行保留，但不参与冷却查询和单人次数统计。正常淘汰后离开不算放弃。
- 放弃成绩在整局结束时结算，结算前保留排位锁；普通模拟仍可使用。
- 服务器重启、内部战斗错误或赛季收尾超时的无效对局不计分，相关放弃冷却撤销。已保存的待结算结果自动重试，唯一流水避免重复加分。

## 管理员赛季管理：仅网页

浏览器登录管理员，访问 `/admin`，账号管理下方新增「赛季管理」。App 内不提供账号与赛季管理页面。

1. 查看当前赛季与运行场次；「暂停 / 恢复新排位」只控制新开局，已开始比赛继续。
2. 「创建下一赛季」填写名称、可选结束时间和各难度积分。胜利分及核心奖励须为偶数，同盟自动减半，失败扣分相同。
3. 选择草稿，点击「更新赛季」。旧赛季停止新排位，最多收尾 10 分钟，归档后开启新赛季；没有运行比赛时立即完成，超时比赛作废。
4. 「当前赛季名称与结束计划」可改名、预约结束时间并选择到期后的草稿。到期自动走收尾流程；不选草稿则归档后等待管理员开启。
5. 已开始赛季的积分规则冻结，新规则通过新赛季发布。旧赛季排行榜、战绩、最高段位与审计记录保留。
6. 「最近对局与异常修正」可填写原因撤销已结算异常对局。按剩余有效流水重算成绩，正确处理 0 分下限并写日志。涉及账号正在打另一场排位时，须等其结束后撤销。

首次启动自动开放「S1 初始赛季」。修改 / 重置密码不改变账号身份；删除后创建同名账号会获得新身份，不继承旧分。

## 数据、备份与恢复

新部署使用私有 `storage/`，可通过 `SP_STATE_DIR` 指定源码目录之外的固定目录，例如 `/var/lib/stronghold-protocol`。旧 `config/` 数据继续兼容读取；迁移与后续更新详见 [PERSISTENCE.md](PERSISTENCE.md)，不要只更换路径而漏掉原文件。

| 文件 | 用途 |
|---|---|
| `storage/auth-users.json` | 账号、密码哈希、权限及不可变账号 ID |
| `storage/ranked.sqlite` | 赛季、成绩、比赛、结算流水、账号锁和审计 |
| `storage/ranked.sqlite-wal` / `-shm` | SQLite 运行中的辅助文件 |
| `mobile/android/.signing/` | APK 更新签名密钥与本地签名配置 |

账号文件、数据库和签名密钥必须保存在私有位置。在线数据库备份包含已提交 WAL 数据，完成后检查完整性，已有目标不会被覆盖：

```bash
npm run ranked:backup
node tools/ranked-backup.mjs
```

工具读取当前数据路径并只备份数据库，**同时保留同一套 `auth-users.json`**，否则账号 ID 不对应。更新源码前暂停新排位、等现有比赛结束、停服，再备份账号与数据库。停服后可复制完整数据目录及 `config/`；运行中不要只复制主库而漏掉 WAL。

恢复时停服、保留现有文件备份，再恢复对应账号文件和数据库，不要把旧 WAL / SHM 混用于恢复后的主库。启动会重试已持久化的待结算结果，丢失内存战斗的进行中比赛作废。本版本不保存完整战斗以供服务器重启续玩。

`SP_RANKED_FILE` 可指定私有数据库位置，新部署默认 `storage/ranked.sqlite`，也可通过 `SP_STATE_DIR` 指定目录；旧部署保留原 `config/` 路径；`SP_RANKED=off` 关闭排位并保留普通模拟，关闭认证时排位不可用。初始化失败会在日志说明，普通游戏仍可使用。结算写入暂时失败时暂停新排位、自动重试，不猜测加分。

## 性能、验证与 APK

排位战斗强制在玩家浏览器 / App 中计算，关闭服务器抽查和完整复算（排位忽略 SP_COMBAT=server 与 SP_VERIFY=all）。服务器仅管理经济、回合、轻量结果校验、积分与数据保存；断线或无有效报告时保留原项目接管机制，会临时增加负载。默认并发上限 `SP_RANKED_MAX_MATCHES=4`，小规格云服务器可先设 1 或 2，再按实测 CPU、内存及延迟调整。

```bash
npm run test:ranked
npm test
npm run ranked:benchmark
```

基准脚本仅测 1 / 2 / 4 / 8 场四人排位的初始化、简报确认及消息分发，记录耗时与内存到 `.cache/ranked-benchmark.json`。不模拟完整战斗，不含网络、数据库和断线接管，不代表云服务器容量。客户端计算只做轻量结果校验，不能提供服务器完整复算的防作弊能力。

新版 `mobile/dist/stronghold-protocol.apk` 使用副本保留的签名，可以覆盖旧版；连接地址仍填写 `http://公网IP:3000`。先部署新版服务端，排位入口和成绩由服务器提供。横屏隐藏状态栏修复保留；账号、密码与赛季管理只通过浏览器。详见 [MOBILE.md](MOBILE.md)。

## 段位图标、对局记录与局内聊天

七套原创 SVG 徽章分别采用青铜盾、白银双刃、黄金羽翼、铂金装甲、钻石晶核、大师紫刃和传奇王冠，显示于大厅昵称、房间座位、局内队友和结算卡片旁，小段位用 I / II / III 标注。

选择模拟协议页面右上角的「对局记录」位于「干员调配」与昵称之间。网页和 App 均可查看自己的本赛季普通赛 / 排位赛，可按单人、同盟及赛制筛选，每页 20 场。点击对局可查看时间、时长、难度、胜负、主线回合、核心通关、每位成员最终阵容、装备、生命和作战统计；排位另显示积分变化和撤销原因。记录与不可变账号 ID 绑定，昵称和密码修改不会丢失记录。不能查询其他账号的记录。

记录按开局时的赛季保存。新赛季列表清空，旧记录仍保存在数据库；旧排位流水仍可在排位中心查看。旧版已有排位自动迁移为记录，升级前未保存的普通赛无法补录。数据库升级自动添加表，不清空积分或账号。进程重启时未完成记录标记中断，不推测胜负。

局内左下角点击「聊天」，输入文字后点击发送；Enter 发送，Shift+Enter 换行（发送时空白规范化），中文输入法选词时不会误发。每条最多 200 个字符，每人间隔 2 秒，只发送到当前对局；正常淘汰仍能发言，主动离开后不能发言。头像右边显示 6 秒气泡，长内容在聊天面板完整查看。对局进行期间在内存保留最近 50 条，重连恢复；胜利、失败、主动放弃、异常结束或房间关闭后立即清空服务端缓存与客户端记录、气泡，结束后重连和下一局无法恢复旧消息；不提供公共大厅频道、邀请卡或一键加入，不把聊天写入数据库。

## 界面动效与资源开销

聊天面板打开 / 关闭、发言气泡出现 / 到期消失、战绩列表和详情切换采用 140–200 毫秒的 CSS 淡入与位移；按钮增加悬停和按压反馈，段位徽章轻微抬起。动画只改变小范围的透明度、位移和缩放，不加入循环背景、粒子、持续光效或滤镜动画。系统开启减少动态效果时自动关闭这些动画。

所有动效由浏览器 / App 本地执行，无新增服务端动画定时器、轮询或推送。聊天清理复用已有结算及房间状态消息，不额外广播，也不操作数据库中的对局记录。聊天面板空闲时不定时刷新，只在发送后的两秒冷却期间短暂更新倒计时；阅读旧消息时不会强制滚回底部。

## 客户端资源包与浏览器账户模式

安卓 App 与 Windows 客户端在登录后、加载游戏页面前准备固定资源包，使用独立的持久文件库。完整版预置全部素材与公开规则；轻量版首次下载 ZIP。已有正确资源不会重复传输，清单版本变化时只下载缺少、变化或损坏文件。代码、认证、账号成绩和对局通信继续实时访问服务器。构建、分发及验证见 [RESOURCE-PACKS.md](RESOURCE-PACKS.md)。

标题页和大厅提供「从服务器更新数据」；开局与局外返回前台时检查最新版本。更新成功并校验全部文件后再切换，对局中不切换。固定资源未变化的代码更新只刷新代码，不重新下载资源。已下载文件保留在客户端私有目录，失败更新保留原清单。版本不一致或本地资源缺失时提示更新，局内请求不回退下载固定文件。

电脑和手机浏览器登录后进入 /account 或 /admin，可改密码、管理用户及赛季；服务器拒绝浏览器的游戏页面、素材、规则和 WebSocket，因此不能创建 / 加入 / 开始 / 继续对局。客户端可游玩，但不能访问账户管理页面或调用密码 / 账号 / 赛季管理接口。浏览器账户页只加载专用脚本和样式，/downloads 仅在主动点击安装包链接时下载客户端。

客户端功能区分依据 User-Agent 的 App 标记，不是不可伪造的设备认证；登录和账号权限始终由原认证模块检查。源码更新仍应等待对局结束并停服，不能在运行的素材目录逐个覆盖不兼容文件。

## 保留现有数据的源码更新

每次更新均沿用现有账号文件和排位数据库，保留账号 ID、密码哈希、角色、禁用状态、赛季、段位、积分、战绩及审计；不会重新初始化默认账号、重开赛季或重建数据库。未知数据库格式会拒绝覆盖。`SP_AUTH_USERS_FILE` / `SP_RANKED_FILE` 的自定义外部文件也应继续使用原路径。

推荐将新版本解压到另一目录，暂停新排位、等现有对局结束并停止服务，然后从新版本目录执行：

```bash
node tools/update-project.mjs --target /opt/Stronghold-Protocol-Ranked --stopped
cd /opt/Stronghold-Protocol-Ranked
npm ci
node --env-file=config/server.env server/index.js
```

`--stopped` 表示已经完成停服，工具不会替你中断对局。工具先备份现有 `config/`、`.env`、`.env.local` 与安卓签名到部署目录私有的 `.backups/<时间>/`，再复制源码；不覆盖任何 `config/`、`.env*`、数据库或 `.signing/`，不删除部署目录的旧文件、素材或数据。备份失败即停止复制。请勿直接用发布包的 `config/` 覆盖部署目录，也不要删除部署目录后重新安装；备份包含敏感数据，不应放进 `public/`。使用外部数据文件时另行备份其原路径。

工具读取部署目录 `.env`、`.env.local`、`config/server.env` 及执行环境中的 `SP_STATE_DIR`、`SP_AUTH_USERS_FILE` / `SP_RANKED_FILE`。完整的 `storage/` 和项目内自定义数据目录都排除并备份，明确配置的外部账号 / 数据库及对应 WAL / SHM 也额外备份到 `external/`，源码复制不会覆盖这些文件。使用其他配置文件时应把对应环境变量提供给更新工具，详见 [PERSISTENCE.md](PERSISTENCE.md)。

APK 继续使用原包名、原签名和递增的 versionCode，覆盖安装保留手机连接设置和 WebView 数据；不要卸载后再安装。构建工具现在读取安卓配置中的 versionCode，避免固定版本号妨碍后续覆盖更新。
