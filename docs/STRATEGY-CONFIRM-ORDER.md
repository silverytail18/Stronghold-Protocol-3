# 策略按就绪顺序选择测试功能

日期：2026-10-11。状态：源码修改与验证完成；按用户要求不打包、不部署、不修改任何界面内容。

## 规则

该功能已改为本局可选测试项，ID `strategy-confirm-order`，版本 `test-1`，名称“策略按就绪顺序选择”，分组“体验优化”。仅多人模式可启用，包括标准／其他难度的多人模式。客户端最低通用测试能力1，无新客户端逻辑。

未启用时，进入策略阶段完全沿用原服务器种子随机排序；启用时，才使用以下确认队列。普通用户默认未开放，管理员可以在现有账号管理后台决定是否公开；管理员按现有权限可直接选择。单人项目禁用。只随房主正式 `room.start` 提交，成员无法启用、不把房间里管理员成员的选择继承给房主；沿用现有清单版本、身份、房主、准备和模式校验。

覆盖只对本局克隆的 `config.bandDraft.confirmationOrder` 设置为 true，缺少该字段时默认 false。没有写入正式配置 JSON 或现有开放设置文件，与回合、商店、禁用和其他测试项可以组合。

启用后，多人对局在“确认本局信息”阶段，服务器将首次收到的有效手动 `g.infoReady` 请求记录到本局队列。进入策略选择时按以下顺序生成初始队列：

1. 已主动确认且当前仍为手动控制的玩家，按服务器收到确认的先后排列。
2. 未主动确认的手动玩家，按原座位顺序补到后面。
3. AI、当前托管及已退出的座位，按原座位顺序补到最后，沿用已有自动选择／退出处理。

重复确认和断线重连不改变已记录的位置。断线但没有启用托管的玩家保留原确认位置；已经退出的玩家不能保留优先位置。自动就绪不会计入手动确认队列；退出托管后，即使就绪状态已经为真，首次有效的手动确认仍可登记。

以服务器接受请求的顺序为准，不采用客户端自行上报的时间。所有客户端继续使用服务器广播的 `draft.order`，不增加协议字段。该记录只存在于当前 Match 实例，不存入账号、配置或成绩文件。

单人模式保留原规则。策略阶段的跳过仍把本人移到末尾；轮次限制、倒计时、超时自动选策略及队友已选策略不能重复选择保持原逻辑。

原策略随机排序与后续机变共用 `rngDraft`。两种开关状态都按原逻辑推进随机数；只有启用测试时覆盖最终队列，避免切换开关就改变后续同种子机变卡牌的抽取序列。机变本身仍沿用原随机规则。
