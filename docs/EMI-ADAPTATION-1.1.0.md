## 3 新排位计分

每个赛季固定 `kind=emi, version=1`；管理员不能在进行中赛季修改权重。普通局不计分。标准难度不能开启排位。险境、绝境、终极可用，单人或2至4名真人合作；不补AI，不限制熟人段位差。

定级3场，单场为：难度底分＋18×通过回合（最多15）＋盟约层数分＋8×协助（最多10）＋胜利奖励。险境/绝境/终极底分30/90/160，胜利奖励50/65/80；三场总分上限2050。盟约分：前120层每层0.5、121至300层每层0.25、301至600层每层0.1、601至999层每层0.04。零回合仍计场并有对应难度底分，不加最低回合门槛。

定级后表现预算为险境25、绝境40、终极50，各分项归一化后加权，合计只取整一次：

| 指标 | 权重 | 达满目标 |
| --- | --- | --- |
| 本人存活回合 | 35% | 15回合 |
| 有效总伤害 | 32% | 100万，含实际领袖血池贡献 |
| 领袖伤害 | 12% | 25万 |
| 已激活盟约层数 | 8% | 999层 |
| 完美回合 | 8% | 15回合 |
| 联防协助 | 5% | 10次 |

神话以下需本人存活至少9回合，神话及以上需11回合，才计入表现分。有效伤害按敌人初始生命预算封顶，联防仅使用漏怪剩余预算，领袖按共享血池实际贡献；只旁观统计，不改变伤害、随机数或战斗行为。缺失/非法的新统计保留为待确认结果，不按零分猜测结算。

神话以下失败没有基础扣分。神话以上险境/绝境/终极基础扣61/44/33，先全额加表现，再用人数败补抵剩余扣分。因此败局可能净加分。开局1/2/3人胜利额外＋30/20/10；败补最高21/14/7，只抵剩余损失。定级不叠人数补偿。连续统治级胜利满足绝境或终极、胜利、盟约至少200层、协助至少3次、有效伤害至少1500万，第二次起额外＋50。

段位：黑铁至超凡每300分一大段、每100分一小段；2100起为神话，2550且活跃排名前50为源能战魂。高段5天没有净加分时隐藏高段排名并遮蔽展示，不扣真实积分。已归档新规则赛季按结束时间查看，历史不会随当前日期继续失活。

长回合和高成长内容更易触及既有分母上限，这是所选原数值的明确取舍。未来要平衡时应发布新规则版本和新赛季，不静默改老战报。

## 4 旧数据与首次切换

服务启动完成 schema 1→2 的兼容结构升级，保留账号和旧数据；这一步不自动清积分。旧服务不支持 schema 2，不能直接把旧服务器程序指向升级后的数据库运行。

管理员在浏览器“赛季与战绩”内查看旧规则赛季清理范围，填写新赛季名称、原因和确认文字“保留对局并清理旧赛季”。存在进行中排位、可靠pending或尚未写入的最终结果时拒绝执行。完成后：

1. 仅定位旧排位规则的赛季，不以“已结束”或赛季名称判断。
2. 旧对局保留胜负、阵容、战斗统计和成员归属，`ranked`改为0，清旧排位回执和关联，显示为普通对局。
3. 删除旧规则赛季的累计积分、段位、榜单、旧积分流水和关联排位运行记录。
4. 保留新规则的草稿、当前赛季、已归档赛季、积分、回执、战报和规则版本。新旧同时存在时不改写新规则记录。
5. 若没有新规则当前赛季，开启填写的新季，所有账号从未定级0/3开始；若已有新规则当前赛季，保留该季，不另开重复赛季。
6. 记录清理原因与旧规则赛季ID；重复执行被拒绝，不会再次清空新数据。

| 既有数据 | 更新处理 |
| --- | --- |
| accountId、登录名、密码、角色、禁用和赞助者 | 保留 |
| 皮肤、技能、模组、培养和调配revision | 保留 |
| 成就、等级、日常和清空统计时间水位 | 保留 |
| 四版本开放、默认版本、内容权限、音乐概率和未知字段 | 保留 |
| 旧排位规则的积分和赛季 | 仅首次清理操作删除 |
| 旧排位对局 | 转为普通对局，保留战斗资料 |
| 新规则赛季历史 | 正常保留，后续软件更新不重置 |
| 没有最终结果的未完成局 | 沿既有停服清理政策处理，不补一个猜测胜负 |
| 可靠最终结果/pending | 幂等恢复；不能为切季而删除 |
| 房间与战斗内存 | 停服后失效，重新开房 |
| 旧进程短会话 | 需要重新登录；新记住设备会话以后可跨重启 |

## 5 以后赛季如何管理

草稿→进行中→收尾→归档。暂停与收尾分开：暂停只阻止新排位，可恢复；收尾拒绝新排位，等待当前局和可靠结果完成，再归档，可立即开启选定草稿。新规则收尾没有10分钟自动作废。普通模拟继续可用。

正常换季独立创建新的积分和定级状态，旧新规则赛季保留，可在榜单赛季选择器查询；软件更新与赛季结束互不等同。账号、展示、常用队友、成就和调配跨季保留。

管理员指定账号定级填写公开编号对应的真实账号、总分及原因；0至1000000整数，不增加场数或胜场，不允许操作有进行中/待结算排位的账号。服务器校验权限，前端隐藏按钮不是鉴权。已结算对局有理由作废时按事件顺序重放后续积分，保留原回执并标记修订，管理员定级事件是明确的重放锚点。

## 9 后续上游适配

更新上游游戏版本时，保留 product 层、纯规则和私有数据，不整库覆盖为 Emi。逐项复核：玩家ID与席位、Battle事件与实际伤害、普通/联防/共享领袖回调、BattleResult序列化、客户端校验、宿主白名单、onLeave/end/dispose顺序、结算公开/私有快照、版本与内容冻结、RoomScreen入口和原生资源契约。

重点回归：普通局不计分；新排位单人/合作和插件只结一次；0回合弃局计场释锁；联防伤害不重复；pending重启不猜零；新旧规则清理不碰新赛季；未来正常收尾留历史；管理员定级鉴权/原因/审计；原账号接管；主界面入口手机可见可点。

只在确认上游机制变化影响旧统计含义时发布新规则版本，已有赛季快照不追随Emi master变化。新游戏内容名称进入当局战报快照；旧记录没有名字快照时显示稳定条目ID，避免用当前内容名称误解释旧局。
