# 0.9.21 账号技能、模组和皮肤同步修复

用户在0.9.20中修改所有干员的技能或模组时均收到“账号干员调配格式无效”，诊断定位为 `accountLoadout.js` 的账号保存PUT请求。日志没有包含原始请求内容；不能据此认定某个干员或精确旧条目有错。单独901种合法技能/模组选择通过原校验；合成旧缓存含 `module:null`、空行、混入的皮肤字段或潜能练度附加字段时，可以复现整份账号调配拒绝。

客户端与服务器共用账号调配结构校验。客户端从旧缓存逐字段恢复合法技能、模组、潜能和练度，剔除不应提交的空行/残留字段；恢复前的账号脏缓存只保留一份在本客户端 `sp.pref.loadout.account.<账号ID>.legacy`，不要求玩家清空本地或服务器存档。账号档案上限仍1000项，不因房间单次提交160项限制裁掉其他版本的合法偏好。原存档版本、账号身份和未知扩展项保持。

皮肤、技能、模组和潜能练度共用同一保存队列和revision。服务器增加账号级 `skins`，并镜像旧 `entries[charId].skin`；旧客户端继续读写原结构时保留已有技能/模组。账号旧皮肤条目会在首次同步时迁移，无需手动重新选择；选择默认皮肤也上传为清除。多人同时编辑按干员及字段合并，不把其他客户端对同一干员技能的修改随模组一起覆盖。

同账号不同客户端在登录、重连和切回前台时恢复服务器最新选择；本地仍未提交的修改先合并保存。没有持续定时轮询。切换账号清理显示中的前一账号选择并取消旧代际未发送任务，不改前一账号云存档。局内仍沿用原来的调配生效阶段与皮肤协议，不放宽干员、模组或内容包准入。

## 更新

本次只更新服务器和动态JS。继续使用0.9.20完整安卓build46（自动横屏功能保持），或已有兼容build45客户端；Windows仍可用0.9.16完整-r2/build45。资源hash `41ebe63b7a079fc34814e9e9714b166dff45f1a681d96035497b6278b7f7314a`、最低构建45、contract2/epoch1/line0.9与签名均不变，不需要重新下载安装客户端或资源。

先在原开服终端按 **Ctrl+C**，等待退出。上传新包到 `/root/updates`，逐行执行，每行成功后再继续：

```bash
cd /root/updates
tar -xzf Stronghold-Protocol-3-server-light-v0.9.21-loadout-skins-20261103.tar.gz --strip-components=1 -C /root/w3
cd /root/w3
npm ci --omit=dev
node --env-file="/root/w3/config/server.env" tools/clear-unfinished-matches.mjs --stopped
node --env-file="/root/w3/config/server.env" server/product/game-server.js
```

最后一行保持运行，下次停服仍按Ctrl+C等待退出。更新包不含真实配置、账号、数据库、调配/统计存档或私钥；覆盖解压保留原服数据，停服清理仅删除无最终结果的未完成对局。按用户要求不添加检查、备份或 `update-project` 命令。

更新后，所有客户端完全退出并重新打开以加载同一版账号同步JS。账号网页刷新即可。先在一个客户端修改一项技能/模组或皮肤，再登录或切回另一个同账号客户端，应恢复服务器最新选择。无需清除应用数据或调配存档。
