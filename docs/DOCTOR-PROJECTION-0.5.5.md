# 博士投影装备替换修复

普通与进阶博士投影共用consume_on_equip_or_delayed分类。普通投影的equip_round_start_upgrade_char处理器把ev.keep设为true，实际占用装备格直到下回合；客户端原先只按分类前缀判断，认为它立即消耗，跳过替换弹窗。服务器延迟分支又没有把replaceUid传给_attach，因此即使已有选择也会替换最早装备的那件，并非随机抽取。

0.5.5的itemAttaches按延迟处理器识别普通投影，已有两件装备时复用现有替换弹窗，必须选择后确认；取消／Esc不发送请求。服务器ev.keep分支传递replaceUid，准确销毁选中装备、保留另一件并装备普通投影。下回合投影销毁并晋升，保留下来的装备按原晋升规则返回整备区。空余装备格不显示替换弹窗；进阶投影立即晋升、不占格，原装备按晋升规则返回而不是被替换销毁。

投影凑足合成时客户端原本就不显示替换弹窗；服务器现在先合成再处理占格，避免合成前误删满装备干员的其他装备。不改正式道具JSON、合成数量、投影生效时机、装备上限、其他内容包、持久化数据或素材；客户端协议和能力32保持。

针对性检查包含单人／联机、战场／整备区、选择任一装备、无操作时库存保持、错误replaceUid拒绝、次回合晋升、空余装备格、进阶投影与合成。真实Chrome复用完整替换弹窗检查：两件原装备及待装道具、取消与Esc、未选时确认禁用、选择第二件后发送replaceUid。普通装备与投影分别验证。

发布包及保留数据安装流程见[服务器更新安装流程](SERVER-UPLOAD-0.5.5.md)。旧0.5.4更新包不包含修复，保持原文件不覆盖。已有兼容联机客户端重开加载新代码，无需重装；资源版本不变。独立安卓单机APK本次不重建。
